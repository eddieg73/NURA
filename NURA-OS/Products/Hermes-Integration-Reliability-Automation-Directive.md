# HERMES SYSTEM INTEGRATION, RELIABILITY & AUTOMATION DIRECTIVE (2026-08-04, founder canonical)

**The operational constitution: every component installed correctly, configured, authenticated, connected, exchanging data, monitored, tested, auto-repaired when safe, escalated when not. "A container running ≠ operational — only a validated end-to-end workflow counts."**

## The core doctrine
1. **Inventory** — machine-readable registry of EVERY app/container/service/DB/API/MCP/broker/webhook/cron/model/agent/integration/domain/cert/storage/backup/secret/vendor: service name+ID, environment, host, internal+external URL, port, protocol, auth, dependencies, health endpoint, data classification, owner, backup policy, recovery procedure, last validation, current status.
2. **Dependency map** — the full graph (upstream/downstream/circular/SPOF/auth/DB/network/storage/vendor/clinical/business) across: Hermes kernel+gateway+agents · Paperclip · MCP gateway · LangGraph · OpenEMR · NURA Bridge/NextGen · Perfex · Chatwoot · Twilio · Gmail · Telegram · WhatsApp · PostgreSQL · Supabase · Redis · Qdrant · Orthanc · OHIF · ThaiRIS · S3 · RunPod · Ollama · vLLM · OpenRouter · OpenAI · Anthropic · Gemini · OpenEvidence · PubMed · FDA · DailyMed · clinical sources · Flutter app · NURA dashboard · monitoring.
3. **The 12 skills** (see the skill `system-reliability-automation-ops`): discovery · health monitoring · e2e integration testing · API validation · MCP validation · database integrity · message/event integrity · security+secrets validation · clinical safety validation · backup+DR · self-healing · incident management (SEV-1..4).
4. **Cron cadence**: per-minute (heartbeats, queue/DLQ, clinical events, failed workers) · 5-min (API/MCP/DB/Redis/Qdrant/OpenEMR/bridge/Orthanc/OHIF/ThaiRIS/Twilio/Chatwoot/disk) · 15-min (containers, CPU/mem anomalies, queue depth, webhook reconciliation, auth failures, event delivery) · hourly (dependency validation, quotas, token+cert expiry, storage growth, model endpoints) · 6-hourly (external sources: OpenEvidence/PubMed/FDA/DailyMed, providers, S3 R/W synthetic, DICOM test routing, FHIR) · daily 02:00 (backups+checksums, security+secrets scan, DB integrity, audit completeness, tenant-isolation test, expiring creds/certs, inventory+map refresh, daily report) · weekly (full synthetic e2e suite, full backup, restoration test, vuln scan, access/MCP/API scope review) · monthly (full DR exercise, RTO/RPO, tenant-isolation audit, clinical-safety validation, model/prompt review, incident trends, cost analysis) · quarterly (penetration test, HIPAA risk review, governance review, drift, retention, privileged-account review).
5. **Health-check contract**: every check returns {service, status, timestamp, latency_ms, checks[], dependencies[], recommended_action, automatic_repair_attempted, repair_result}.
6. **Self-healing boundaries**: MAY auto-restart unhealthy containers, reconnect networks, re-pool DB connections, replay idempotent events, DLQ failed events, refresh permitted tokens, clear approved caches, restart nonclinical workers, scale within limits. MUST NEVER: delete production data, drop DBs, change firewalls, rotate critical secrets, modify clinical records, approve clinical decisions, change meds, modify signed docs, release critical results, change claims, disable security, deploy untested code, irreversible actions.
7. **Observability**: unified dashboard (status/uptime/integrations/API/MCP/DB health/queue depth/DLQ/errors/latency/CPU/RAM/disk/GPU/backups/certs/security+clinical alerts/incidents/deployments/cron failures/last e2e) + structured logs (timestamp, tenant, service, env, correlation ID, event ID, agent ID, severity, action, result, error code, data class). No raw PHI/secrets in logs.
8. **Alerting**: SEV-1 = immediate multi-channel to sysadmin+clinical+security+owner · SEV-2 = owners immediately · SEV-3 = ticket + daily report · SEV-4 = maintenance review. Dedupe, group, cooldown, suppress during active incident, recovery notification.
9. **The daily report**: the `# Hermes Daily Operations Report` format (overall status · critical incidents · failed integrations · backup status · security status · clinical safety status · resource utilization · scheduled jobs · recommended actions).
10. **Implementation order**: discover → inventory → dependency map → gap analysis → credential validation (never exposed) → health checks → structured logging → dashboards → alerts → cron jobs → synthetic e2e tests → approved self-healing → backup validation → restoration tests → clinical safety validation → security validation → readiness report → prioritized remediation backlog.
11. **Definition of Done**: every approved service inventoried+owned · every dependency documented · every critical service health-checked · every integration e2e-tested · every cron monitored+alerted · every DB backed up+restore-tested · every API/MCP validated · clinical safety + tenant isolation tested · security findings documented+remediated/accepted · dashboards+alert routing operational · incident procedures documented · Hermes detects/classifies/reports/responds · final readiness report generated. **Never claim "fully operational" without the complete end-to-end validation passing.**

## The final deliverables
Complete system inventory · architecture/dependency diagram · integration matrix · MCP registry · API registry · cron-job registry · health-check registry · backup/recovery matrix · security findings report · clinical safety validation report · e2e test report · failed-integration remediation plan · dashboard spec · incident-response plan · production-readiness scorecard · prioritized engineering backlog (each item: problem, affected service, operational/clinical/security impact, root cause, correction, owner, priority, dependencies, validation+rollback procedure).

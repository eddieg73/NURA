## 2. THE GITHUB VERIFICATION LANE (the external check before any new adoption)
- The sources: the awesome-hermes-agent catalog (local ✓) · the skills.sh registry (npx skills add — the mattpocock-lane!) · the trending-repos (the weekly scans!) · the mattpocock-35 (local ✓ the top-3 converted!)
- The verification: the candidate-repo → the stars/activity/license/currency (the GitHub-API!) → the supply-chain-scan (the injection-check!) → the DECIDE (INTEGRATE/STUDY/MONITOR/SKIP!)
- The gate: NO external skill enters the library without the verification pass (the security-mandate 08-06!)

## 3. THE SELECTION MATRIX (the determination)
```
TASK → LOCAL (the 508-index by category!) → GITHUB (the gap-fill!)
        → DECIDE (the max-3 + the mandatory-safety!)
```
1. Classify the task (the category-map!)
2. The local-index query (the description-scan!)
3. The gap-check: the local has no match → the GitHub-lane (the verify → the convert → the add!)
4. The max-3 load + the mandatory-safety-first!
5. The post-check (the gap → the create/patch; the redundancy → the dedupe!)

## 4. THE CADENCE
- Weekly: the catalog-curation cron (the GitHub-scan → the install-queue!)
- Monthly: the selection-index refresh (the 508-count re-audited + the gaps-built!)
- The drift-audit: the stale/duplicate skills flagged (the dedupe-queue!)

## 5. The verification
- The selection-trace in every task reply (the "skills: X, Y" line!)
- The library's growth tracked (the 508-baseline! the monthly-deltas!)
- The process itself lives in the skill-selection skill (the SKILL.md = the operating copy!)

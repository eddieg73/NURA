# TEAM TOOLS — the human-layer toolkit (2026-08-04)

**The doctrine: plain markdown everywhere, editor-agnostic, zero lock-in, $0 tools. The vault is the single source of truth; everything below is an optional surface.**

## Recommended (by role)
| Role | Surface | Notes |
|---|---|---|
| Founder (iPad) | Obsidian (vault sync) — the ONLY surface needed | the CouchDB livesync = automatic |
| Hermes (agent) | the terminal + filesystem (the agent path) | — |
| Content writers (Jade +) | **MarkText** (Win/macOS/Linux, free, MIT) — the clean drafting surface | live preview, typewriter mode, PDF/HTML export, plain .md → the content pipeline |
| Docs/Technical Writer | MarkText or VS Code + docs-as-code (MkDocs-class) | the SOPs + API docs → the vault |
| Engineers (Amrit/Oussama) | VS Code + the repos | the Flutter/Symfony lanes |
| Ops (Alexis) | Obsidian (web/iPad) + the vault | the setup packages + the trackers |

## The standards (the MarkText lesson applied)
1. Plain .md files — never a proprietary format (any editor can open the company's docs).
2. The live-preview principle: write for the reader, format rarely — the vault renders everything anyway.
3. Export paths: PDF/HTML via the existing pipelines (authoritative-document-compilation) — no editor-dependent exports.
4. No accounts, no cloud lock-in for the docs layer — the vault + the fleet are the cloud.

## MarkText install (when a desktop writer needs it)
- Releases: https://github.com/marktext/marktext/releases (Win/macOS/Linux installers)
- The niche: distraction-free drafting → the content/video pipeline + the docs library.
- Caveat (from the review): slow update cadence + no plugin ecosystem — a pen, not a platform.

# TECHNICAL WRITER, TRAINING & IMPLEMENTATION SPECIALIST — the role spec (2026-08-04)

**Position:** Technical Writer, Training & Implementation Specialist · **Funnel:** the AI hiring manager · **Signer:** the founder

## 1. MISSION
Make NURA understandable and operable: the documentation system (API, architecture, deployment, SOPs, user manuals), the training program (clinicians, staff, customers, new hires), and the implementation enablement (the onboarding packages, the go-live playbooks) — with the doctrine: **if it isn't documented, it doesn't ship; if it isn't trainable, it won't be adopted.**

## 2. CORE OWNERSHIP
**Documentation:** API reference (OpenAPI-generated + curated) · architecture docs (the fleet, the kernel, the Sidecar) · deployment guides (the 3-node map, the compose patterns) · SOPs (the ops playbooks — incident, backup, channel promotion) · user manuals (the provider workspace, the dashboards, the admin portal) · developer docs (the MCP lanes, the skill system) · regulatory documentation support (the compliance evidence vault).
**Training:** clinician onboarding (the workflows, the safety gates, the AI-boundary training) · staff/admin training · customer training (the lighthouse go-live) · new-hire enablement (the role-spec 90-day contracts) · the training library (videos, guides, quick-refs).
**Implementation:** the onboarding package per role (the Alexis setup package!) · the go-live playbooks (the customer checklist: environments, credentials, mapping, testing, training, launch) · the release notes · the change-communication.

## 3. REQUIRED STACK & EXPERIENCE
Markdown/AsciiDoc · docs-as-code (MkDocs/Docusaurus-class) · OpenAPI · screenshots/video capture · LMS/learning tools · Confluence/Notion-class (the Obsidian vault fluency) · the ability to interview engineers AND clinicians and produce both an API doc and a provider quick-ref.
**Experience:** 5+ yrs technical writing · 2+ yrs healthcare/regulated software (preferred) · API documentation · SOP development · training delivery · the discipline of versioned, reviewed, evergreen docs (docs rot = defects).

## 4. RECOMMENDED CERTIFICATIONS
STC certification · docs-as-code training · instructional design (ADDIE-class) · HIPAA training · HL7/FHIR familiarity. Certs ≠ ability — the library decides.

## 5. THE PRACTICAL EXAM (the gate)
Given the Sidecar integration architecture, deliver: (1) the API reference page for one endpoint (the document-submission flow) with the auth, the schema, the errors, the examples; (2) the deployment runbook for one node (the Edge n8n lane); (3) the provider quick-reference card for the abnormal-result workflow (one page, safety-first); (4) the new-hire onboarding checklist for one role (the QA engineer); (5) the training outline for the lighthouse go-live. **Evaluation: accuracy, clarity, completeness, the safety discipline (no ambiguity in clinical instructions), the docs-as-code quality.**

## 6. FIRST 90-DAY DELIVERABLES
**1-30:** the docs system (structure, standards, CI publishing) · the API docs baseline (the kernel + the MCP lanes) · the SOP library v1 · the release-notes cadence.
**31-60:** the provider manuals (workspace, queues, escalation) · the admin manual · the new-hire onboarding kits (per the role specs) · the training library v1.
**61-90:** the lighthouse go-live playbook + the training sessions · the implementation checklist · the documentation audit (everything real, nothing stale) · the evergreen process.

## 7. KPIs
Docs coverage (features with current docs) · docs freshness (staleness age) · training completion + comprehension · go-live playbook adherence · support deflection (docs resolving tickets) · onboarding time per new hire. **Targets: stale production docs = 0 · untrained-on-safety gates = 0 · go-lives without a playbook = 0.**

## 8. THE JD SUMMARY
The Technical Writer, Training & Implementation Specialist makes NURA learnable and deployable: every API documented, every SOP current, every clinician trained on the safety gates, every customer handed a playbook — because in healthcare, documentation is a safety feature.

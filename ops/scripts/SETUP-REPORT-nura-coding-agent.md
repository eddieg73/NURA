# NURA Coding Agent — Setup Report

The NURA Coding Agent is operational as a read-only decision-support service: a stdlib-only Python engine at `scripts/nura-coding-agent.py` that ingests chart/encounter text (stdin, `--chart`, `--chart-file`, or the built-in `--self-test`) and emits the SKILL-mandated shape — CANDIDATES (code + HCC + RAF + supporting quote), GAPS, PROMPTS, and the `DRAFT — PROVIDER APPROVAL REQUIRED` status on every row. It runs two lanes: a deterministic rule-based matcher grounded in the extracted CMS-HCC V28 workbook sidecar (`nura-coding-ref.json`, rebuilt from the ranked quick reference, the full 590-code ICD-10→HCC map, V28 traps, MEAT guide, and interaction bonuses via `nura-coding-ref-extract.py`), and a Med42 pass over the Ollama API (`med42:latest` first, `biomistral:latest` fallback) that enriches candidates with verbatim evidence quotes and surfaces clarifications — degrading gracefully to rule-based-only when Ollama is unreachable (verified live: lane reported `med42 (med42:latest) + rule-based` on 127.0.0.1:11434). Doctrine is enforced in code: history never coded as active, missing specificity always produces a clarify-ask (e.g., CKD "stage 3" returns N18.30 with a prompt, never an assumed 3b), DM+CKD never silently linked into E11.22, V28 trap conditions (HTN alone, OSA, hyperlipidemia, CAD without angina, etc.) flagged without HCCs, RAF values always from the reference and labeled approximate, and interaction bonuses reported as estimates only. The test encounter (72yo, DM2, CKD 3b, chronic systolic CHF) verified correct candidates: E11.9→HCC 37 (0.166), N18.32→HCC 328 (0.07), I50.22→HCC 85 (0.323), plus the DM+CHF bonus (~0.121) and the HTN trap note. The agent writes nothing to disk or to OpenEMR/Perfex/CarePilot; its only network egress is the Ollama API, and every output is a provider-approval candidate, never an autonomous diagnosis.
